# SETUP_SUMMARY.md Template

Write this file to `<project>/SETUP_SUMMARY.md` at the end of a successful (or partially-successful) bootstrap run. It is the audit trail: future invocations can read it instead of re-detecting everything.

Fill in real values for every placeholder. Leave a line out only if the corresponding phase was skipped (mark the phase as "skipped" in the Notes section).

---

---

## Writing tips

- The summary is for the user, not for me. Plain language, not log dumps.
- Capture commands as the user would type them, with their real project path - not `$PROJECT_PATH`.
- If a phase was skipped, say so explicitly. A missing row is ambiguous; "GitHub auth: skipped (user chose GitLab only)" is unambiguous.
- Don't include API keys, OAuth tokens, or anything from `~/.config/gh/hosts.yml` etc. Tool versions and paths are fine; secrets are not.
